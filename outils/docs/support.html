Pour les utilisatrices, l'informaticien du service — et pour l'éditeur

Procédure de support

Comment demander de l'aide, ce qu'il faut joindre, dans quels délais on répond. Des délais qui se tiennent valent mieux que des délais qui impressionnent. Version {{VERSION}}.

1. Demander de l'aide

  1. Écrivez à {{SUPPORT}}. Un message par problème. Pas de support par téléphone sans rendez-vous.
  2. Dites ce que vous essayiez de faire, ce que l'application a fait, ce que vous attendiez — en quelques lignes.
  3. Joignez, si vous le pouvez, le rapport de diagnostic : Aide › Rapport de diagnostic pour le support…, puis « Enregistrer le rapport… ». Il ne contient ni nom de document, ni contenu, ni nom de personne ; il n'est envoyé nulle part, c'est vous qui le joignez, après l'avoir relu.
  4. N'envoyez pas le document en cause s'il est sensible. Si le problème en dépend, on vous aidera à le reproduire avec un document fabriqué : l'éditeur ne veut pas recevoir vos dossiers.
  5. Indiquez la version (« Aide › À propos ») et le système (Windows 10/11, macOS).

Les délais sont en jours ouvrables (lundi au vendredi, hors jours fériés du canton du siège de l'éditeur). Ils sont des engagements de moyens : un correctif dépend de la reproduction du problème, et il passe par la construction, les tests et la publication d'une version signée. Le niveau est fixé avec vous au premier échange ; en cas de doute, c'est le plus élevé qui s'applique jusqu'à ce qu'on sache.

4. Les correctifs, et comment vous êtes prévenus

  • Un correctif sort sous forme d'une nouvelle version numérotée, avec ses notes de version, son archive signée, son empreinte. Vous l'appliquez comme toute mise à jour (voir le guide d'administration, §7).
  • Un défaut du niveau 1 qui touche tous les clients fait l'objet d'un avis : sur la page de téléchargement de l'éditeur, et l'éditeur écrit directement aux clients concernés (adresse de leur compte ou de leur offre). La version corrigée est signée « importante » : l'application la présente alors comme une mise à jour importante à son lancement, et ses notes de version disent ce qui était en cause.
  • Une version « candidate » peut vous être remise pour confirmer qu'un correctif résout votre cas, avant sa publication en « stable ».
  • L'éditeur n'a aucun moyen de forcer une mise à jour : le produit ne se connecte à rien. C'est vous qui posez l'archive. Il n'y a pas non plus de remontée automatique qui lui dirait quelles versions tournent chez vous.

5. Pour l'éditeur : traiter une demande

  1. Accuser réception dans le délai du niveau, et fixer le niveau avec la personne. Ouvrir une ligne dans le registre de suivi : date, client, version, niveau, résumé.
  2. Lire le rapport de diagnostic : version et canal, système, mode de rangement des données, état de licence, journal de session, connexions refusées (attendu : aucune). Chercher d'abord : mauvais mode de rangement (donnees-par-utilisateur.txt.txt), archive non signée refusée, licence invalide, essai terminé, fichier verrouillé par une collègue.
  3. Reproduire avec un document fabriqué (jamais celui du client). Le dépôt contient des générateurs de PDF d'essai (outils/test-e2e/aide.js, outils/test-caviardage).
  4. Niveau 1 : geler les mises en circulation (aucune version stable tant que la cause n'est pas comprise), prévenir les clients concernés, écrire un test qui échoue avant le correctif et passe après.
  5. Répondre avec : ce qui a été compris, le contournement s'il y en a un, la version qui corrige, la date visée. Ne jamais promettre une date qu'on ne tient pas.
  6. Clore : noter la cause, le correctif, la version, et si la documentation doit changer (guide, notes de version, ce document).
Modèle de réponse

« Bonjour, merci pour votre message et votre rapport. Ce que nous comprenons : … Pour l'instant : … (contournement). Le correctif est prévu dans la version X.Y.Z, que nous visons pour le … Nous vous écrivons dès qu'elle est publiée. »

6. Ce que cette procédure suppose

Qu'une personne répond aux messages aux jours ouvrables, qu'elle sait publier une version signée et qu'elle tient le registre de suivi. Si l'éditeur change ces moyens, il change ce document avant de changer ses délais.
